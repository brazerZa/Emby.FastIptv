Stream Metadata

Emby needs the real codec of a channel before it can play it, and it turns the advertised video codec into an ffmpeg input decoder override. Getting it wrong breaks playback outright, so pick where that information comes from.
The plugin reads the first part of the stream itself and takes the real codecs, resolution and audio layout from the MPEG-TS tables, which takes a few hundred milliseconds instead of the seconds Emby's own probe needs. Results are cached, so tuning the same channel again costs nothing. Anything the probe cannot read with certainty falls back to Emby's own probe for that one channel, so playback is never based on a guess.
Hard deadline for one probe. On timeout the channel falls back to Emby's probe.
Ceiling, not a cost: the probe stops as soon as it has what it needs. Codecs are known within the first packets; only the resolution needs a key frame, which on a long-GOP channel can be a few MB in.
How long probe results stay valid; they survive restarts. Saving a tuner clears them, which is what to do if a provider changes a channel's codec.
Fast but a guess: every channel is advertised with the codecs below, which breaks HEVC/4K playback (audio with black video) because Emby then offers those channels to clients as h264. Only an escape hatch for providers no probe can read.
